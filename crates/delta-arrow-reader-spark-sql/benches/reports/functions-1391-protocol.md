# Function execution protocol (#1391)

This reference and runbook is for maintainers measuring
[#1391](https://github.com/mag1cfrog/delta-arrow-reader/issues/1391). It measures
execution and reports exclusions. Product source is pinned to staging commit
`cde51da6dca2203f53dfe702dc06914931bd7845`. Existing #1379, #1380, #1381 and #1385
statements, evidence bytes and test outcomes stay unchanged.

## Freeze and inventory

Commit the new harness, [manifest](../functions/manifest.json),
[native registry](../functions/native-registry.json),
[schedule](../functions/schedule.json), drivers and this protocol as commit A.
Build one Linux release `functions` binary from A. Run the complete preflight
with that binary, then commit only `functions/preflight-receipt.json` as B.
This receipt freezes final classes, eligibility and both ANSI comparisons before
any clocks. Timing requires a clean exact B, ancestry from A, an A-to-B diff
containing only the receipt, matching protocol source hashes and the same binary
SHA-256. Do not rebuild or change statements between preflight and timing.

The first preflight identified eight setup errors. Six native date controls
now preserve NULL before casting the interval text. Two map constructors
now use disjoint nonnull keys and retain their nullable values. The revised
protocol runs these eight cases before freezing eligibility. It reuses the
earlier observations for byte-identical manifest rows after verifying the
same release binary, fixture, schedule and original plan hashes. The
receipt records the original and corrected evidence. If the binary bytes
differ, run the complete preflight with the final binary. The original
paired value and executed type mismatches remain excluded.

`inventory.py --check` parses the top-level registration tuples, follows the
scalar module list and last-write HashMap behavior, and reconciles public runtime
keys. The effective inventory has 457 scalar, 84 aggregate, 81 window and 9
generator entries: 631 category/name pairs and 559 distinct spellings. Four
earlier window definitions for `first`, `first_value`, `last` and `last_value`
are retained as shadow evidence. Aliases sharing a registration expression each
keep their own row. The 69 `F::unknown` placeholders remain explicit exclusions.
Table functions such as `range` are outside the issue's four registry classes.

Every entry carries a registry anchor, implementation anchors, frozen column
SQL and a projection, or an explicit reason why no execution can be timed.
The native catalogue is an executable snapshot from a plain default DataFusion
session. Native references include explicit casts and SQL compositions where
needed. Equal names alone do not establish equivalence. Failed native planning,
execution or result encoding remains a setup failure. It never silently becomes
a semantic mismatch or a Spark-only classification.

The manifest's paired classes are candidates until full preflight. `same`
requires the same SQL, actual physical ScalarUDF/AggregateUDF/WindowUDF equality,
matching physical arguments, complete output rows and executed types in both
ANSI modes. The only normalization beyond identity/name projections is for the
listed native unary math kernels generated by `datafusion-functions/src/macros.rs`:
their executor reads arrays and applies a floating-point operation without
reading ConfigOptions. For those kernels, compare UDF identity, argument trees
and return types while ignoring the unused Spark configuration extensions.
Keep all physical function evidence and original plans. Unknown window executor
types cannot establish `same`. Same functions receive verified inventory rows
with empty timing fields. The two requested workloads are timed even when their
kernels are shared.

## Input and execution

Generate one seeded in-memory Arrow table with 1,000,000 rows. The fixed seed is
`0x13915eed20261119`, with sequential row IDs. Every sixteenth row is NULL in
each data column. ID, the 4,096-way window partition key and stored 250,000-way
high-cardinality key are nonnull. `fixture` records all executed input types,
NULL counts, batch count and seed. The table includes signed BIGINT and INT,
DOUBLE, DECIMAL(15,2), UTF-8 STRING, BINARY, DATE, UTC TIMESTAMP, BOOLEAN,
ARRAY, MAP and STRUCT. Integer values include negative numbers. Numeric domains
stay within ordinary math domains. The protocol measures these particular inputs.

Store nested arrays, arrays of structs, valid WKB, vector arrays, HLL/theta
sketch bytes and AES ciphertext as columns before query execution. Decryption
does not include encryption, and flatten/inline do not include collection
construction. The public fixture AES key is `0123456789abcdef`. The ciphertext is
AES-128-ECB with PKCS7 padding of the stored binary `aGVsbG8=`. Other explicitly
nested helpers/casts in a statement are part of that statement's measured cost.
No literal-only statement stands in for a varying column call. Random functions
without valid column arguments and session/file identity functions have explicit
source exclusions. `shuffle(arr)` is Spark only and uses successful execution as
its eligibility condition.

Use one MemTable shared by separate plain native and Spark-configured sessions.
Both use one worker, one target partition, batch size 8,192, UTC and a 2 GiB
DataFusion pool limit. Disable only the aggregate-statistics substitution in
both sessions so COUNT cannot become a precomputed constant. Spark runs once
with ANSI off and once with ANSI on. All queries use the public native or Spark
planner and the resulting physical execution stream.

Preflight drains every result. Scalar, window and generator outputs retain ID, and grouped aggregates retain their grouping keys. Compare all encoded output rows
as multisets, including NULLs and duplicate multiplicities, across batch
boundaries. Sort list/set aggregate contents explicitly where their order is
unspecified. Executed Arrow data types must match exactly. Compare the types and values directly from the returned batches.
Check actual batch types against the physical schema, including empty output
schemas. Floating-point bits are preserved except that NaNs have one comparison
encoding. Do not accept a row/type mismatch in either mode: exclude the entire
paired function from all clocks and report the difference.

An untimed standard CoalesceBatchesExec guard at each physical input source
counts the rows actually consumed. Every accepted native and Spark execution,
including a `same` execution, must consume exactly 1,000,000 rows. The guard is
absent from timed plans. Complete encoded results live only in bounded process
memory and are dropped between cases.

Analytic/rank windows use their mandatory source-defined frames. LAG and LEAD
omit an explicit frame. Other aggregate windows use four preceding rows plus
the current row, so list/string/sketch outputs do not grow quadratically with
the million-row input. Generator output counts can exceed the input count. Use exactly 1,000,000 input rows as the denominator.

The only extra workloads are DECIMAL division with ROUND, retaining the prior
DECIMAL(18,2) boundary casts, and stored high-cardinality GROUP BY with COUNT(*),
BIGINT SUM and DECIMAL MAX. They use this issue's new in-memory input. Their
numbers do not replace or revise #1380's historical measurements.

## Commands and receipt

From the Spark workspace, build using the existing Linux release settings and
the owned cache. The coordinator serializes Cargo work and all execution:

```sh
CARGO_TARGET_DIR=/home/hanbo/.cache/delta-arrow-reader/costs-168-2026-11-19 \
CARGO_BUILD_JOBS=2 CARGO_PROFILE_RELEASE_DEBUG=1 \
cargo +1.96.0 build --locked --release --bench functions \
  --message-format=json-render-diagnostics
```

Resolve `BINARY` from the compiler-artifact JSON, not a guessed executable path.
Keep an external build receipt with `source_commit` A, `binary_sha256`, the exact
`command`, `profile: "release"`, `target: "functions"`, `instrumented: false`,
toolchain verbose version and build environment. From the repository root:

```sh
python3 crates/delta-arrow-reader-spark-sql/benches/functions/inventory.py --check
python3 crates/delta-arrow-reader-spark-sql/benches/functions/run.py check
python3 crates/delta-arrow-reader-spark-sql/benches/functions/run.py preflight BINARY EVIDENCE/preflight --build-receipt BUILD_RECEIPT
```

Review and commit the resulting eligibility receipt as B. Do not convert
preflight failures into product fixes. Then execute the original schedule once:

```sh
python3 crates/delta-arrow-reader-spark-sql/benches/functions/run.py measure BINARY EVIDENCE/once --frozen-commit B --build-receipt BUILD_RECEIPT
python3 crates/delta-arrow-reader-spark-sql/benches/functions/run.py summarize EVIDENCE/once crates/delta-arrow-reader-spark-sql/benches/reports
```

## Schedule and interpretation

Pin fresh processes to CPUs 2,3,4,5 and run them serially on the Linux worker.
The committed schedule fixes three process replicas, one warmup and three
retained executions for each function/configuration. Share the generated table
within each fresh shard of at most sixteen cases. Rotate case order by one third
per replica and reverse alternate shards. Native A/A control arms alternate
A/B, B/A, A/B. The three main configuration orders rotate native/off/on,
off/on/native and on/native/off. There are no pilot timings, profiles, unchanged
repetitions or concurrency checks.

Each iteration separately executes the function statement and the plain
projection of the union of its referenced input columns. Alternate their order.
Logical/physical planning, table generation, plan rendering, output destruction,
RSS reading and JSON serialization stay outside clocks. Each clock starts at
`execute_stream` and ends after stream completion. Record the signed difference
`(execution_ns - projection_ns) / 1,000,000`, including negative costs.

Take the median of three retained signed costs within each process, then the
median of three process medians. Report min, max and inclusive IQR of process
medians, fixed-input throughput and raw execution/projection samples. For paired
functions A/A repeats the native function with its projection. Spark-only A/A
uses the same-column native projection against itself. The control floor is the
maximum of the absolute A/B median gap and half of either arm's process spread.
For a paired comparison, also include half of either main arm's spread in the
effective floor. A positive Spark-minus-native cost strictly above that floor
is a measured regression. Report signed native cost and ratio. Leave the ratio
empty with its reason when native incremental cost is nonpositive or within
its control floor. For the two close-noise workloads, report whether their
signed difference clears this input's measured floor.

Preflight has 300 seconds per process and six hours overall. Timing has 120
seconds per case, 2,000 seconds per shard process and twelve hours overall.
Linux address space is capped at 12 GiB per process, including encoded result
memory outside DataFusion's pool. No shape is downsampled or replaced to fit a
bound. A case failure, missing arm or missing replica makes the entire function
untimable. Retain its raw partial evidence and continue the remaining original
schedule without rerunning completed samples. Each retained iteration flushes
a sample outside its clocks, so it survives a later case or process failure.
After a required cell fails, record any later cells of that function as
skipped. Continue the scheduled cells for other eligible functions. Hard process failures identify
missing shard cells. An overall deadline leaves the unrun cells explicitly
excluded. These exclusions have no accepted timing fields.

The CSV has one row per function/category and Spark ANSI configuration, including
all exclusions and verified same functions. Its compressed raw JSONL and physical plan archive sit beside it. The committed
preflight receipt remains in the functions directory. The summary ranks every above-floor paired
case by excess ns/input-row and every measured Spark-only case by its signed
cost. Rank the thirty distinct Spark-only function IDs by their highest ANSI
cost and show both modes. The maintainer's report reads the referenced source
and states the per-row work and which input-invariant work could run once per
batch. Source anchors are evidence pointers, not automated optimization claims.
Keep the two close-noise workloads separate from function ranks. No fix or new
issue is part of this measurement.
