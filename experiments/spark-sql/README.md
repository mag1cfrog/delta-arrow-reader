# Spark SQL extraction experiment

The [owning issue](https://github.com/mag1cfrog/delta-arrow-reader/issues/113) defines the scope, coverage matrix, reduction rules and completion criteria. This first slice contains the query corpus and a full-Sail observation tool for review. Vendored Rust code and the extraction runner are the next slice after review.

- `inputs.json` fixes the full-Sail version, session settings and input views.
- `queries.jsonl` gives each query a stable ID, family, SQL and setting overrides. `seed_rows`, `seed_fields` and `seed_arrow_types` preserve expectations from the earlier extraction probe. They are not automatically regenerated by the observation tool. New cases still need reviewed expectations from an independent Apache Spark reference before they become compatibility assertions.
- `reference.py` records full-Sail planning/execution errors, schemas and values. `host_only` cases describe adapter registration or read-only policy and never execute against full Sail. `known_boundary` records an existing gap; it does not exempt the case from review.

Validate the files with the Python standard library:

```bash
python3 experiments/spark-sql/reference.py --check
```

For observations, use a separate Python environment containing `pysail==0.7.1` and a compatible Spark Connect client with its dependencies. The initial run used `pyspark-client==4.2.0` and CPython 3.13.12. This environment is a test tool and is not a dependency of the Rust frontend.

```bash
python experiments/spark-sql/reference.py --out target/spark-sql/sail-reference.json
```

The command checks rows and specified field names for 19 existing successful seed queries, then records the other cases as observations. `comparison="ordered"` preserves sequence checks for ordered multirow seeds; other seeds compare row multisets with duplicates retained. Arrow-type checks are pending in the Rust runner. Full Sail can contain compatibility gaps itself. The independent Spark oracle, Rust result/type/error assertions, and real Delta/lifecycle checks are pending. The Python reference views do not prove Delta scan behavior. Reuse the existing fixtures under `tests/reader/` for those Rust checks instead of rebuilding them in this tool.

Keep raw observations under `target/`. Review expected results separately. For unordered queries, the future comparator must use row multisets and preserve duplicates; names, types, NULL behavior, decimal precision and timestamp settings need their own checks. Partition-dependent functions need invariant checks rather than literal partition IDs.

The planned source location is `experiments/spark-sql/vendor/sail/`, with pinned provenance and upstream notices. This directory will use an isolated Cargo workspace during extraction. Any later move into the public crate structure follows the measured adoption decision.
